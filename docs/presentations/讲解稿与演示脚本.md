## 开场 20 秒（定调）

## 第 4 页 · 超白话术语（照着念）

| 词 | 你怎么说 |
|----|----------|
| 因子 | 一个算得出来的分数，像表格里新加的一列，用来猜谁相对更强 |
| 挖因子 | 自动试很多种算分公式，不是人手写一个 |
| IC | 这个分数和后来涨跌沾不沾边；只说明单独还行 |
| 过拟合 | 试太多把运气当规律，像网格搜索只报最高分 |
| 未来函数 | 偷看当时还不知道的信息，考试偷看答案 |
| 因子库 | 通过验收的特征登记册，不是无限加列 |
| Lift | 去掉旧特征已经解释的部分，还看还有没有新贡献 |
| Agent 角色 | 分工明确的虚拟同事，不是一个模型包办 |

## 多 Agent 主线口播（第 7–11 页）

### 为何拆多角色（第 7 页）

> 一个大 prompt 会把「想方向、写代码、自评」搅在一起，模型容易自我辩解。  
> 我们拆成：有人提案、有人写表达式、**代码真算分**、有人专职唱反调。  
> 还有跨 session 记忆，避免每轮失忆实习生。

### 编制（第 8 页）

> **4 个 LLM 角色 + 1 个确定性 Evaluator**（注意不是 5 个 LLM）。  
> - Librarian：翻旧账 / 记新账  
> - Hypothesis：提「为什么可能有效」  
> - Coder：翻成白名单语法的表达式  
> - **Evaluator：Python 真算，不调模型**  
> - Critic：keep / 改公式 / 改方向 / drop  

> 生成与验收分离：LLM 不当既是运动员又是裁判。

### 一轮流程（第 9 页）

> recall → 提案 → 写表达式 → 实测 → Critic → 否决回路或下一轮。  
> Session 末：写记忆、导出 candidates，还可自动组 Lift。

### 记忆（第 10 页）

> 挖穿区（试 ≥15 次全挂）→ 避开；未探索区 → 优先；库已覆盖 → 求正交；Lift 拒过 → 别换皮再来。

### 防翻车（第 11 页）

> 语法沙箱、结构模板配额、多重检验记账、holdout、session 末与 lift-test 共用裁决函数。  
> LLM 没配好直接报错，不静默假挖。

## 预判问答

| 问 | 答 |
|----|-----|
| 为何不用一个 Agent？ | 职责纠缠、缺对抗评审、缺记忆；team 把生成与验收拆开。 |
| Evaluator 是不是第五个 Agent？ | **不是 LLM 角色**，是确定性求值节点，口径写死为「4 角色 + Evaluator」。 |
| 和 AutoGPT 类系统差在哪？ | 金融时间 PIT、表达式白名单、统计护栏、Lift 入库门禁、manifest 可回放。 |
| LLM 胡说怎么办？ | 语法失败 heal；护栏/Critic drop；记忆避免重复踩坑。 |
| 实盘了吗？ | 纸面撮合；实盘是路线图。 |
